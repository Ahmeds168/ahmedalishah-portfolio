Decentralized Document Notary

Solidity · React · Node.js · Supabase · Cloudflare R2 · Sepolia testnet

The problem: proving a document existed in a specific state at a specific time, without trusting a single company's database to not quietly change it later. Traditional notarization solves this with a person and a stamp; this project solves it by hashing the document client-side and writing that hash to a smart contract on Sepolia — so the proof of existence lives on a public, append-only ledger instead of in someone's private table.

The interesting engineering problem wasn't the smart contract itself (that part is genuinely simple) — it was everything around it. Files themselves are too large and too sensitive to put on-chain, so the actual documents live in Cloudflare R2, with Supabase handling user accounts, metadata, and the mapping between a file and its on-chain hash. The contract only ever sees a hash, never the document.

Deployed across three different platforms doing three different jobs — Vercel for the frontend, Render for a small backend service, Sepolia for the actual notarization — which turned out to be a good, if accidental, lesson in keeping deploy responsibilities cleanly separated.

On-Chain Voting dApp

Solidity · Hardhat · React (Vite) · ethers.js

A minimal voting contract, deliberately kept small so the interesting part could be the frontend: a ballot UI styled to look like an actual official paper ballot rather than a typical crypto dashboard. The goal was to test whether a blockchain voting interface could feel familiar to someone who's never touched a wallet before — same visual language as a polling booth, with the wallet connection and transaction confirmation handled quietly in the background.

Hardhat handled local contract testing and deployment scripting; ethers.js bridged the contract calls to the UI. It's a small project, but it's the direct descendant of my final-year university project — same core idea (votes as immutable on-chain records), much cleaner execution.

Groq Chat App

Node.js · Express · React (Vite) · Groq API

A full-stack chat interface built to get hands-on with fast LLM inference — Groq's API serves responses fast enough that the usual "typing indicator" UX patterns barely matter. The Express backend handles the API calls and keeps the key server-side; the Vite/React frontend is deliberately simple, just a textbox and a response stream, so the focus stays on the model interaction rather than UI chrome.

This project doubled as a testbed for prompt engineering technique — testing how system prompts, temperature, and message history structure change response quality in a low-latency setting.

Election System Using Blockchain (final-year project, SISC)

Hyperledger Fabric · IBM Blockchain VS Code Extension

My university final-year project, and the one that got me into blockchain in the first place. Unlike the public, permissionless setup of the two projects above, this uses Hyperledger Fabric — a permissioned blockchain, meaning only known, vetted participants (in this case, representing election authorities) can validate transactions. That's a deliberate choice: for something like an election, you often want accountability and known identities behind each validating node, not full anonymity.

Built and deployed through the IBM Blockchain VS Code extension, which handles a lot of the Fabric network scaffolding that would otherwise be painful to configure by hand.
